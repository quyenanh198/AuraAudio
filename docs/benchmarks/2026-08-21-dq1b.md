## Before/After — dq1 (10 fixtures) → dq1b (12 fixtures, post-review)

Code review of `6f15b8e` (docs/benchmarks/2026-08-21-dq1.md) flagged that
`aura_worker.ghost_filter.MIN_DURATION_S=0.15` was derived from a suite
whose fastest case was eighth notes @130bpm (0.196s notes) and could
plausibly delete a genuine fast note that never got a chance to prove
otherwise. This report adds two 16th-note-run fixtures
(`guitar_sixteenth_run_c_major_140`, `piano_sixteenth_run_c_major_140` —
nominal note length ~0.091s, comfortably under the 0.15s floor) to close
that gap, per `BENCHMARK_SUITE_VERSION` bump `2026-08-21-v1` →
`2026-08-21-v2`. This section compares the two runs; it is **not** a
before/after of a code change — no production code changed between dq1
and dq1b, only the fixture suite grew.

### What the new fixtures found (the actual re-derivation result)

Measuring basic-pitch's REAL raw output (at the production per-instrument
thresholds) against both new fixtures found:

- The smallest TRUE POSITIVE raw note duration across the enlarged suite
  is **0.1858s** (from `guitar_sixteenth_run_c_major_140`) — still
  comfortably above `MIN_DURATION_S=0.15`.
- The largest GHOST raw note duration below the floor is **0.1393s**.
- **`MIN_DURATION_S` is unchanged (0.15)** — it sits cleanly between those
  two measured values, confirmed rather than moved. See
  `aura_worker.ghost_filter`'s "RE-DERIVATION" docstring paragraph and
  `workers/transcription/tests/test_fast_passage_regression.py`'s
  `test_ghost_filter_duration_floor_is_not_the_bottleneck_on_a_fast_passage`
  (asserts filtering never reduces onset F1 below the unfiltered value on
  this fixture — i.e. the duration floor provably isn't deleting real
  notes here).
- The real, disclosed limitation on fast passages is basic-pitch's OWN
  onset/frame detection merging closely-spaced onsets into fewer, longer
  notes at these thresholds — not this filter. Piano is worse affected
  (0.476) than guitar (0.857): a wider frame-threshold sweep including
  these fixtures (`docs/benchmarks/2026-08-21-threshold-sweep.md`) found a
  piano `frame_threshold` that helps this fixture (0.2 → 0.85 on this
  fixture) also regresses the original 4 piano fixtures beyond the DQ-1
  gate's 0.05 margin (e.g. `piano_melody_c_major_100` 1.000 → ~0.94,
  `piano_two_hand_wide_range_e_minor_130` 1.000 → ~0.80) — see
  `aura_worker.instrument_thresholds`'s docstring for the full trade-off.
  `PIANO_THRESHOLDS` is left unchanged deliberately: protecting the
  already-verified original-suite result over the new fixture's score.
